# SafeTransfer: показ и питч для жюри

## Подготовка до запуска таймера

1. Из корня выполните `cd web`, затем `npm install` и `npm run dev`. Дождитесь запуска приложения.
2. Используйте чистый профиль браузера без старых демо-решений. Откройте клиент http://localhost:3000 во вкладке **А**. Нажмите **RU**; убедитесь, что доступен профиль **Айгерім С.**
3. Откройте ссылку **«Панель банка»** в новой вкладке **Б** и дождитесь загрузки. Обе вкладки должны использовать один адрес `http://localhost:3000`; не смешивайте его с `127.0.0.1`, другим портом или другим браузером.
4. В чистом хранилище панель показывает **300 переводов**, из них **22 со средним/высоким риском**. Это базовые данные до действий ведущего, а не целевые показатели после показа. Вернитесь во вкладку А.
5. Выберите ширину окна не меньше 1280 px; при размере 1280×720 форма и риск видны рядом. Дождитесь загрузки обеих страниц заранее, чтобы первая компиляция dev-сервера не вошла в тайминг.
6. После нажатия сценария дождитесь балла: проверка начинается после 400 мс без изменений ввода. Не меняйте поля вручную — кнопки уже задают профиль и фиксированное время для воспроизводимости.

Все действия ниже работают с демо-данными. Не вводите реальные имена, реквизиты или секреты. Операции и решения остаются демонстрационными.

### Что важно не перепутать

- Видимые чипы **«Ночью · новому»** и **«Серия переводов»** имеют доступные длинные названия «Крупный ночной перевод новому человеку» и «Много быстрых переводов». Во время показа ориентируйтесь на короткие подписи.
- Результаты заданы реальным движком: **0/низкий, 60/высокий, 85/высокий, 35/средний**. Последний сценарий — не только частота: он также включает новое устройство.
- **85 — балл, не вероятность 85%.** В подозрительном сценарии сумма весов 20 + 40 равна 60, но применяется минимальный итог 85.
- Счётчики после кликов меняются. Не называйте их доказанными предотвращёнными потерями или измеренной точностью.
- **«Разрешить»** доступно аналитику после отдельного подтверждения; у клиента при высоком риске такой обходной кнопки нет. Для показа блокировки выбирайте именно запись из ленты, а не произвольную строку таблицы.
- Сценарии показывают фиксированное демо-время, а не текущие операции банка. Лента видит новые ID; смена `held → pending_review` обновляет ту же запись без дублирования.

### Если показ прервался

| Ситуация | Что сделать и сказать |
| --- | --- |
| Проверка не загрузилась | Нажмите **«Повторить проверку»**. Скажите: «Без результата проверки демо не сообщает об успешной отправке». Если API недоступен, используйте заранее подготовленные изображения, прямо назвав их скриншотами. |
| В ленте много записей | Ищите последний запрос Айгерім С. → Руслан И., 20 000 ₸, **«На проверке»**. При необходимости выберите фильтр **«Статус перевода» → «На проверке»**. Новая запись может появиться на очередной проверке локальных данных через две секунды. |
| Браузер запретил хранение | Покажите предупреждение и скажите: «Решение доступно в этой сессии, но сохранение между вкладками/перезагрузками требует разрешённого хранилища». Для живой ленты используйте подготовленный профиль с доступным localStorage. |
| До старта выбрано KK | Нажмите **RU**, затем начните скрипт заново. Смена языка не меняет правила риска. |

## Питч на 5 минут

Полный трёхминутный показ выше — самостоятельный формат. В пятиминутном питче используйте **сжатую демонстрацию на две минуты**, чтобы осталось время на технологию и ограничения.

| Время | Блок | Содержание и ключевая фраза |
| --- | --- | --- |
| **0:00–0:35** | Проблема | «Клиент может подтвердить мошеннический перевод сам. Нужно объяснить риск до отправки и дать аналитику контекст, а не просто ещё один код подтверждения». Не приводите неподтверждённые цифры ущерба. |
| **0:35–1:05** | Решение | «SafeTransfer связывает клиентскую проверку и банковский разбор: один балл, конкретные признаки, понятное действие и RU/KK». Покажите два экрана и обозначьте, что все данные синтетические. |
| **1:05–3:05** | Демонстрация | 1:05–1:25 — «Обычный перевод», 0 и успех. 1:25–1:50 — «Ночью · новому», 60 и приостановка. 1:50–2:10 — «Серия переводов», 35 и подтверждение. 2:10–2:35 — «Подозрительный счёт», 85 и запрос проверки. 2:35–2:55 — лента, карточка, подтверждение блокировки. 2:55–3:05 — KK. Для точных кликов используйте основной скрипт, сокращая комментарии. |
| **3:05–3:45** | Технология | Покажите диаграмму README. «Чистая функция считает признаки, API возвращает решение, шаблоны объясняют причины. Next.js и TypeScript объединяют интерфейс и API. Тесты проверяют правила, но не доказывают точность на банковском потоке». |
| **3:45–4:30** | Масштабирование | «Банковский адаптер должен получать реальные профили и оконные признаки на сервере. Далее — авторизация, аудит, идемпотентность и проверенный режим отказа. ML можно добавить рядом с прозрачными правилами; LLM — только для текста по подтверждённым признакам». Отдельно скажите, что этого промышленного контура в MVP ещё нет. |
| **4:30–5:00** | Следующие шаги и запрос | «Нужен пилот на законно подготовленных размеченных данных: измерить ложные тревоги, полноту обнаружения и задержку, откалибровать пороги и проверить работу аналитика. Просим обратную связь по сценарию интеграции и критериям пилота». |
